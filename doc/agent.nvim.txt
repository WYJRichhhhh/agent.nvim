*agent.nvim.txt*  本地 AI CLI 的单会话终端                     *agent.nvim*

要求 Neovim 0.11+。CLI 负责登录、模型和历史；插件负责终端窗口与进程。

快速操作                                               *agent.nvim-quickstart*

在 Agent 中输入时，按键会发送给 CLI。要执行 Neovim 命令，先依次按：
    Ctrl-\，Ctrl-n        退出终端输入模式，进入终端普通模式
然后可以：
    q                     隐藏窗口，保留进程、任务和未提交输入
    ?                     打开本帮助
    i                     返回 CLI 输入模式
    :Agent select         打开后端菜单，切换 Claude Code / Codex
    :Agent stop           停止 CLI 进程并删除终端 buffer

关闭帮助窗口用 :q；再执行 :Agent open 回到原会话，按 i 继续输入。
普通模式下 :Agent hide 也可以隐藏窗口。直接关闭 Agent 窗口通常保留会话；
删除终端 buffer（如 :bd!）会结束进程。退出 Neovim 也会结束会话。
不要把 Ctrl-c 当作隐藏键：它会发送给 CLI，可能中断当前任务。

插件没有默认全局快捷键。README 的 lazy.nvim 示例配置了：
    <leader>aa            打开/聚焦；已聚焦时隐藏（普通模式）
    Alt-a                 打开/聚焦/隐藏（普通模式和终端输入模式）
    <leader>as            打开后端选择菜单（普通模式）
在 CLI 输入时要用 <leader>as，先按 Ctrl-\，Ctrl-n。
这些映射需由用户配置；<leader> 的实际按键取决于个人配置。

切换后端                                               *agent.nvim-switch*

执行 :Agent select，选择菜单中的另一个后端，然后确认停止并切换。
选择当前后端只聚焦已有会话；取消确认保留进程与未提交输入。
确认后停止旧 CLI，再启动新 CLI：当前任务和未提交输入会中断。
每个 Neovim 只有一个会话，切回旧后端不会自动恢复旧进程或历史对话。
只显示已注册且命令可执行的后端；缺少选项时运行 :Agent health 检查 PATH。
Alt-a 只负责显示/隐藏，不会重新弹出后端菜单。

命令                                                   *:Agent*
    :Agent                  同 :Agent focus
    :Agent help             打开本帮助
    :Agent start [backend]  明确启动新会话；拒绝替换运行中的会话
    :Agent resume [backend] 恢复历史；Codex 使用 codex resume，需先退出 CLI
    :Agent open [backend]   显示已有会话，没有会话时启动
    :Agent hide             隐藏窗口，进程继续运行
    :Agent toggle           按窗口可见性切换
    :Agent focus            不在 Agent 时聚焦，已经聚焦时隐藏
    :Agent editor           返回代码窗口，保留 Agent 面板、会话和代码视图
    :Agent select           选择后端，切换运行中的后端前要求确认
    :Agent stop             停止进程并清理 buffer
    :Agent status           查看后端、目录、job 和显示状态
    :Agent health           检查版本与后端可执行文件

Codex 修改跟踪                                         *agent.nvim-review*

可选开启，需要 Node.js 22+、macOS/Linux，以及支持 --remote / App Server /
capability-token 的 Codex。已验证 macOS + Codex 0.163.0。
Claude 可独立开启 Hooks 修改跟踪，见下方 Claude 说明。
>
    require('agent').setup({
        codex = { enabled = true },
        window = { layout = 'right', width = 0.42 },
        review = { follow = true },
    })
<
原生 TUI 负责输入与审批；观察连接只接收结构化修改事件。
成功修改后，原编辑窗口打开真实文件，新增标绿、删除显示红色虚拟行，
批量事件仅打开最后一个文件，清单保留全部；焦点保留在 TUI。
阅读代码或隐藏 Agent 时保留视图并继续记录修改，回到 Agent 后自动跟到最新修改。
开始编辑才自动暂停；编辑或手动暂停后须 :Agent follow 恢复。不覆盖未保存内容。

    :Agent changes          当前会话保留轮次的修改文件清单（路径去重）
    :Agent diff             整轮 unified diff，只读红绿对比
    :Agent filediff         最近选择文件的补丁
    :Agent follow           切换自动跟随，恢复时回到最近修改
    :Agent pause            暂停自动跟随
    :Agent code             聚焦最近选择/修改的源文件
    :Agent turns            选择当前插件会话内的历史轮次
    :Agent next / prev      在对应源文件中跳到下一处/上一处修改

差异 buffer：q 返回原 buffer；gf 打开光标所在文件。不会停止 CLI。
历史轮次/删除文件显示补丁，不把旧差异标到当前源文件上。
已安装 Telescope 时文件列表可搜索并预览 diff；回车在代码区打开红绿差异。
选择文件暂停自动跳转，取消不改变跟随。默认保留 20 轮，:Agent turns 按轮查看。
review.picker="ui_select" 强制使用 vim.ui.select；默认 "auto" 自动发现 Telescope。
这些命令需从 Neovim 普通模式执行：CLI 输入状态先按 Ctrl-\、Ctrl-n。
README 提供 <leader>ar/ad/ag/aD/af/ae/ah/an/ap 映射示例；插件不创建全局按键。

数据来自 fileChange 与 turn/diff/updated，仅记录实际收到的成功修改。
Git 项目默认以任务前本地快照补充 shell/脚本写入，条目标记 [Git]。
无法准确归因并发写入；忽略/二进制/超大文件与快照预算之外的内容可能缺失。
不等于 Git HEAD 差异或完整工作区修改。
提交前仍应检查 git diff。大补丁跳过并提示，允许同项目已注册 worktree。
:Agent gitdiff 可选择 worktree 查看相对 HEAD 的已跟踪文件差异，包含已有
修改与暂存修改，不包含未跟踪文件；可以用于检查旧版未捕获的已完成任务。
自动差异仅从新任务开始采集，无法重建未知的旧任务前基线。

隐藏保持服务和会话。停止/切换/删除终端/退出 TUI 或 Neovim 时清理服务。
CLI 自然退出后已收到的差异保留到显式停止/重启。连接错误会报告并停止，
不会偷偷退回另开一个 CLI。空会话落盘前会等待订阅，不要求用户重新启动。
依赖不足时 :Agent health；:Agent status 查看连接状态。终端停在初始输入框时
waiting 表示尚未落盘，首次任务开始后会继续订阅。

高级选项（均为默认值）：
    codex.enabled           false，是否启用 Codex bridge
    codex.node              'node'，Node 可执行文件路径
    codex.startup_timeout   15000，服务启动超时（毫秒）
    review.follow           true，初始自动跟随状态
    review.history_limit    20，保留轮数（本次插件会话内）
    review.max_diff_bytes   2097152，单个补丁的大小上限
    review.restrict_to_cwd  true，限制为启动目录及允许的 worktree
    review.worktrees        true，发现同一 Git 项目的已注册 worktree
    review.git_fallback     true，任务前快照与工具完成后检测脚本写入
    review.max_snapshot_bytes 33554432，快照总预算（32 MiB）
    terminal.capture_mouse  true，Agent 聚焦时临时启用鼠标，离开恢复

关闭 codex.enabled 即使用原来的直接终端。启用时 command[1] 必须能执行
app-server 子命令；shell argv 包装方式只适用于直接终端模式。
更详细的依赖、进程所有权、登录继承和范围说明见中英文 README。

Claude 修改跟踪                                      *agent.nvim-claude*
>
    require('agent').setup({ claude = { enabled = true } })
<
需要 macOS/Linux、Node.js 22+、Git，以及支持 --settings/Hooks 的 Claude Code。
已实测 macOS + Claude Code 2.1.210 的真实文件修改与红绿展示。Windows 用纯终端。
使用会话专用 Hooks，保留原生 TUI、登录与审批；不修改用户/项目设置文件。
若 command 已有一个 --settings JSON/文件，会在启动时合并选项与 Hooks。
UserPromptSubmit 建立轮次；Edit/Write/MultiEdit/NotebookEdit 前后比较实际文件；
Git 项目可补充脚本与已注册 worktree 的写入。与 Codex 共用上述全部审查命令。
:Agent resume claude 在 CLI 退出后打开原生历史选择器，不重建历史补丁。

阅读代码不暂停，返回 Agent 自动追到最新修改；编辑或手动选择文件后暂停，
:Agent follow 恢复。历史/删除文件显示只读补丁，清单默认保留最近 20 轮。

限制：需接受目录信任并允许 Hooks；disableAllHooks、组织策略、--bare 或
--safe-mode 可能禁用观察。waiting 表示尚未收到 Hooks，检查 Claude /hooks。
不会绕过策略；claude.enabled=false 可退回纯终端。无法旁接任意已有 CLI。
非 Git 目录只覆盖上述文件工具；Shell/MCP/后台写入需要 Git 兜底或不可见。
未接入 bashEditDiff、FileChanged 或历史日志；Notebook 展示 JSON 文本补丁。
并发/部分失败写入可能被统计；同 session_id 子 Agent 写入归父轮，不同 ID 忽略。
不提供子 Agent 独立审查，后台跨轮写入可能归后续扫描。大小、范围限制仍适用。
原生缓存与 Git 快照各自受 max_snapshot_bytes 限制，补丁受 max_diff_bytes 限制。
Hook 客户端静默失败不阻止 Claude；超时可能漏报。CLI 自然退出保留已收到记录。
更完整的验证范围与限制见 README 的 Claude 章节。

    claude.enabled          false，是否启用 Claude Hooks 适配器
    claude.node             'node'，Node 可执行文件
    claude.startup_timeout  15000，启动超时/未收到 Hooks 时提示的等待毫秒数
    claude.hook_timeout     10000，每次 Hook 客户端最长等待毫秒数

代码讲解                                               *agent.nvim-code*

开启 Codex/Claude 修改适配器后，code.enabled 默认 true；本次启动向 CLI 接入
agent_nvim_editor MCP，提供 show_code / clear_code，不修改全局 MCP 配置。
可以问：「使用 show_code 在左侧打开业务核心代码，标记关键行，先不要修改文件。」

show_code 接受 locations 数组，每项有 file 和 ranges；每个范围含从 1 开始的
start/end（含末行）、可选 label 和 expected_text（该范围全文）。只加载首文件，
其他位置从列表选择。讲解高亮链接 Visual，与修改 diff 红绿区别；焦点默认留在
Agent，工具可显式 focus=true。讲解会暂停修改跟随，防止视图立即跳走。

    :Agent locations        选择讲解位置（建议 <leader>al）
    :Agent clear            清除讲解高亮和列表（建议 <leader>ac）
    :Agent code             优先聚焦当前讲解，否则聚焦修改文件
    :Agent next / prev      有讲解时导航关键范围/文件，否则导航修改块
    :Agent follow           清除讲解并切换修改跟随

源码窗口/目标 buffer 未保存、范围越界、片段过期、范围外/不存在/二进制/过大文件
会返回工具错误，不覆盖内容。编辑/重载标记文件会清除过时高亮；再次导航会校验。
隐藏保留讲解，显式停止或切换清理；自然退出保留。clear 不自动恢复修改跟随。
所有讲解键须在 Neovim 普通模式使用，终端输入时先 Ctrl-\、Ctrl-n。

工具需要新启动的 CLI 才能发现；原生 MCP 权限/组织策略仍生效，按 CLI 提示审批。
Agent 决定是否调用工具，必要时明确要求 show_code；不保证业务语义判断正确。
自定义/纯终端后端不注入；尚无 AST 跟踪、历史导览或自动发送未保存 buffer/选区。
详细架构、验证和限制见中英文 README 的代码讲解章节。

    code.enabled            true，开启会话 MCP（需 Codex/Claude 适配器）
    code.max_locations      20，每次展示的位置数量上限
    code.max_ranges         50，每个位置的范围数上限
    code.max_highlight_lines 1000，每个位置累计高亮行数上限
    code.max_file_bytes     2097152，最大文件字节数

配置                                                   *agent.nvim-setup*
>
    require('agent').setup({
        backend = 'auto',
        cwd = function() return vim.fn.getcwd() end,
        window = {
            layout = 'float', width = 0.85, height = 0.85,
            border = 'rounded',
        },
        terminal = {
            start_insert = true,
            hide_key = false, -- 可设为 '<M-a>'，仅在 Agent buffer 生效
            show_hint = true, -- 每个 Neovim 实例首次启动显示操作提示
        },
    })
<
默认只有终端普通模式下的 q 和 ? 局部映射，不占用 CLI 输入中的 q 或 ?。
关闭首次提示可设置 terminal.show_hint = false；仍可随时 :Agent help。

缩放与滚动                                             *agent.nvim-scrolling*

终端 / tmux zoom 改变尺寸后自动调整浮窗、分屏和 PTY，保留原进程和输入。
Agent 聚焦时临时启用 mouse，滚轮交给内层应用；回代码区恢复原设置。
如果 tmux 已进入 copy-mode，请先退出。设置 terminal.capture_mouse=false
可以关闭鼠标接管。查看 Neovim 保留输出：Ctrl-\、Ctrl-n 后 Ctrl-b / Ctrl-f；
i 返回输入。原生 CLI 的历史仍由其自身滚动功能管理。

生命周期                                               *agent.nvim-session*
    隐藏和重新显示复用同一个进程与终端 buffer。
    cwd 在启动时绑定，后续 :cd/:lcd/:tcd 不改变已有进程的目录。
    CLI 退出后保留输出，:Agent start 明确重新启动。
    停止或退出 Neovim 后，历史恢复取决于 CLI 自身的持久化能力。
    同后端 :Agent resume 优先沿用原启动目录。
    插件直接执行命令参数数组，不启动 shell、不读取 shell rc 或别名。
    注册后端、环境变量与详细配置见 README.md / README.zh-CN.md。


主动代码展示
MCP 服务和 show_code 工具说明要求：代码定位、实现讲解、原因分析及相关追问，
先读源码，再展示关键行，最后讲解；无需用户输入工具名。普通任务不会逐次展示。
这是模型指引，无法保证每次调用；用户要求不切换时应保持视图。更新后重启会话。

Codex 还会向插件自有 App Server 追加 developer_instructions 展示规则：通过 config/read
解析并保留已有指令后追加，不修改全局配置或项目文件。项目导览（如“从入口开始
了解项目代码”）也要求先展示入口。更新插件后重启 Neovim，开启新会话。
Claude 目前使用 MCP 指引，不使用此 Codex 专属会话覆盖。
